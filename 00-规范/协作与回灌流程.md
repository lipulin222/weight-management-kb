# 科普内容页 · 协作与回灌流程

> 适用：产品/设计（本地 HTML） ↔ 医学编辑（异地改文案、加图）
> 核心原则：**文案的唯一正本是《文案稿》，HTML 由脚本从文案稿生成。** 编辑不碰 HTML。

---

## 一、产物与责任人

| 产物 | 位置 | 谁改 | 说明 |
|---|---|---|---|
| **文案稿** | `文案稿/W01-….md` … `M06-….md`（**一页一稿，12 份**） | 医学编辑 | 唯一正本：导语 / 节标题 / 条目 / 图注 / 插图需求；文件名与页面 HTML 同名 |
| **图片** | `assets/img/编号-序号-语义.svg` | 设计（按编辑给的需求） | 设计源文件放 `assets/img/_src/`；已上线的插图先内联在页面里 |
| **HTML 页面** | `01-用药早期/`、`02-用药中期/` | 脚本生成 | 人不要手改；改样式改 `00-规范/科普内容页模板.html` 后回灌 |
| **样式模板** | `00-规范/科普内容页模板.html` | 产品/设计 | 视觉的唯一正本 |
| **规范** | `00-规范/提示词、判据、索引清单` | 产品 | 文案与视觉规则 |

## 二、版本命名

- 文案稿：`文案稿-用药早期与中期-v4.1.md` → 每轮审校**另存**：`…-v4.1-审校1-医学编辑-20261016.md`
- 不要在原文上直接覆盖（保留上一版才能对比"这轮改了什么"）
- HTML 版本号记在 `00-索引-减重科普内容页清单.md` 的「变更记录」里

## 三、给医学编辑的三条改稿规则

1. **只改字**：改句子、删句子、加句子都行；不要动 `#`、`##`、`####`、`-`、`**`、`>` 这些结构符号。
2. **一句话一行**：条目一条一行，不要把几条合并成一段（合并后脚本对不回原结构）。
3. **加内容就加行**：新增条目直接在对应小节下加一行 `- ……`；新增小节加一行 `#### 04 小节名`。
4. **改完不要另存为 Word / PDF**：保留 `.md`（或在线文档导出 `.md`），我这边才能自动回灌。

### 图怎么给

- 在 `##### 配图（第 X 节）` 下的「画什么」写一句（例：`画一张注射部位示意图：腹部/大腿/上臂三个区域，肚脐周围留空`）
- 正图文件名：`W05-01-周均值.svg`（编号-序号-语义），矢量优先
- 图注也是文案，在「图注：」那一行改
- 图规范：宽 352（16:9 → 352×198，顺序图横幅 352×118），图内文字 12px，只用品牌色，必须标"示意图"

## 三之二、双栏编辑器（推荐给医学编辑用）

本地工具：**左边 HTML 实时预览 · 右边 Markdown 直接改 · 定稿一键发布到 GitHub**。编辑全程不碰 HTML 代码。

### 启动（产品/设计侧·两种方式）

**方式 A · 需要服务（可一键发布 GitHub）**
1. 双击 `start-editor.bat`（会起一个本机服务，窗口别关）
2. 浏览器打开 **http://127.0.0.1:8190/editor.html** ← 用 `127.0.0.1`，不要写 localhost
3. 端口被占用时脚本会自动往后找，看窗口里打印的实际端口；也可以 `powershell -ExecutionPolicy Bypass -File .\start-editor.ps1 -port 8300`

**方式 B · 离线版（打不开服务时的兜底，双击即可）**
- 双击 `editor-offline.html`：文案和样式都已内嵌，不需要服务、不需要联网
- 左边预览 / 右边改 md 都一样；改完点「导出文案稿」下载 md，发回给产品侧回灌并发布
- 缺点：不能一键发布 GitHub（发布要走方式 A 或产品侧脚本）

### 页面能力
| 区 | 作用 |
|---|---|
| 左上 · 页目选择 | 12 页任选，右侧文稿与左侧预览跟着切；右上小圆点＝有未保存改动 |
| 左 · 预览 | 真实手机宽度（420px），改右边文字**实时更新**（停止输入 0.25 秒后刷新）；已上线的插图会照原样带出来 |
| 右 · 文案稿 | **当前这一页**的 Markdown，直接改字；`#`、`##`、`-`、`**`、`>` 这些符号不要动 |
| 按钮 · 保存本页 | 只把当前页写回它自己的 `.md`，不动页面（草稿阶段随便存） |
| 按钮 · 保存全部 | 12 份 md 一起写回 |
| 按钮 · 定稿并发布 | ①保存 12 份 md → ②**回灌生成 12 个 HTML** → ③`git add/commit/push` |

### 一页一稿的格式（编辑只需要认这 5 种行）
```markdown
# W05 · 体重多久称一次、怎么记        ← 页编号 + 标题（别改编号）
> 导语：体重每天上下浮动很正常，盯单日数字容易白紧张。
## 01 什么时候称                      ← 节：## + 编号 + 节标题
- 每周**固定一天**的早上，起床后…      ← 条目；**…** 表示加粗，符号要成对
## 配图（第 03 节）                    ← 有配图的页才有
- 画什么：…                           ← 给设计的需求（编辑补一句）
- 图注：看那条深色的周均值线…           ← 图上/图下要显示的那句话
> 李医生 · 内分泌科 · 主治医师 · 更新 2026.10.13   ← 三件套审核行，别删
```

### 发布前必填
`减重服务-科普内容\publish.config.json`：
```json
{ "remote": "https://github.com/用户名/仓库名.git", "branch": "main", "messagePrefix": "科普内容更新" }
```
- `remote` 留空时：只在本机提交，不推送（可先跑通再补）
- 首次发布会 `git init` 并把远端配好；之后每次发布 = 一次提交 + 推送
- 推送失败（权限/网络）会把 git 的输出直接显示在页面底部，按提示处理

### 端口被占用时
`powershell -ExecutionPolicy Bypass -File .\start-editor.ps1 -port 8300`（脚本也会自动往后找可用端口，看窗口打印的实际地址）

## 四、回灌流程（我这侧）

1. 收到编辑回传的文案稿（+ 图片）
2. 跑回灌脚本：解析文案稿 → 重建 12 篇 HTML（结构、样式、版头、吸底按钮、三件套按模板生成）
3. 图片落位到 `assets/img/`，按规范嵌入（示意图标注 + 图注）
4. **出《本轮改动清单》**：哪一篇、哪一条、从"什么"改成"什么"——你按清单抽查，不用通读
5. 更新索引清单的版本记录

## 五、回灌脚本的输入输出

```
输入：文案稿/W01-….md … M06-….md（一页一稿，12 份）
   ▼
解析规则（每份 md 只对应一页）：
  # W01 · 标题            → 页标题
  > 导语：……              → .art-hd__lead
  ## 01 节标题            → 节编号 + 节标题
  - 条目文字              → ul.ck > li（**xx** 还原为 <b>）
  - **名称** — 说明       → .item > .nm + .ds
  ## 配图（第 N 节）/ - 图注：… → figure（插图沿用页面里已有的 svg）
  > 李医生 · …            → 三件套审核行
   ▼
输出：01-用药早期/*.html、02-用药中期/*.html（页头/版头/三件套/吸底按钮按模板生成，样式取模板）
```

## 六、常见坑

| 坑 | 处理 |
|---|---|
| 编辑直接改了 HTML | 不要合并：把他的改动手工抄进文案稿，再由脚本重新生成 |
| 文案稿被存成 Word/PDF | 退回要求 `.md`；Word 会引入全角符号和不可见字符 |
| 图片文件名改了 | 沿用原命名；改名会导致页面断链 |
| 两轮审校混在一个文件里 | 按轮次另存文件，分别回灌 |
| 编辑想改视觉（字号、颜色） | 走模板：改 `科普内容页模板.html` 后回灌，不在单篇里改 |
