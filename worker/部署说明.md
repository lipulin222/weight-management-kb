# 在线保存后端 · 部署说明（暂时不用，备查）

> **现状：不启用。** 已改为纯本机方案（双击 `start-editor.bat`，保存在本机，页面只提示「保存成功」）。
> 下面这套 Cloudflare Worker 留作备查，真要启用再照做。

静态页面（GitHub Pages）没有后端，写不了仓库。这个 Worker 就是代持 GitHub 凭据的那个后端：
浏览器 → Worker → GitHub API → commit 进仓库。凭据只存在 Worker 里，**不进仓库、不下发到浏览器**。

## 一、生成 GitHub 令牌（2 分钟）

1. GitHub → 右上角头像 → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
2. Token name：`kb-save`
3. Expiration：选一个到期时间（建议 90 天，到期再来换）
4. Repository access：**Only select repositories** → 选 `weight-management-kb`
5. Permissions → Repository permissions → **Contents：Read and write**
6. 生成后**复制保存**（只显示一次）

## 二、建 Worker（2 分钟）

1. 打开 https://dash.cloudflare.com → 注册/登录（免费，不用信用卡）
2. 左侧 **Workers & Pages → Create → Create Worker** → 名字随意（如 `zz-kb-save`）→ **Deploy**
3. 进入该 Worker → **Edit code** → 把 `worker/save.js` 的内容整段粘进去（覆盖默认代码）→ **Deploy**
4. 同一页面 **Settings → Variables and Secrets → Add**，逐个添加：

| 变量名 | 值 |
|---|---|
| `GH_TOKEN` | 第一步复制的令牌（**点 Encrypt 存成密钥**） |
| `GH_OWNER` | `lipulin222` |
| `GH_REPO` | `weight-management-kb` |
| `GH_BRANCH` | `main` |
| `SAVE_TOKEN` | 自己编一个口令，比如 `zzkb-2026`（**Encrypt**） |
| `ALLOW_PREFIX` | `文案稿/`（只允许写文案 md，页面 HTML 由本机回灌脚本生成） |

5. 复制 Worker 的地址，形如 `https://zz-kb-save.xxxxx.workers.dev`

## 三、告诉前端地址（1 分钟）

把仓库根目录的 `保存服务.json` 改成：

```json
{
  "endpoint": "https://zz-kb-save.xxxxx.workers.dev",
  "token": "你设置的 SAVE_TOKEN"
}
```

提交推送即可（也可以把这两项发我，我来改）。

## 四、验证

浏览器打开 `https://你的worker地址/` → 应看到
`{"ok":true,"service":"zz-kb-save","repo":"lipulin222/weight-management-kb"}`

然后在索引页点「改稿」，右上角会显示 **「在线保存 · 直接写入仓库」**，改完点「保存本页」或「定稿并发布」，
几秒后 GitHub 仓库里就多了一个 commit，Pages 约 1 分钟后更新。

## 说明与兜底

- **只写 md**：线上保存只动 `文案稿/*.md`，页面 HTML 仍由 `回灌.ps1` 生成（保证样式一致）。所以线上保存后，需要有人跑一次回灌。
- **没有配置也能用**：没配 Worker 时，编辑器自动回到「只读 · 导出 md」，不会报错。
- **换平台也行**：有 Vercel / Netlify / 自己的服务器，把 `save.js` 的 `export default { fetch }` 包一层对应入口即可，逻辑不用改。
- **安全边界**：最坏情况是拿到地址的人乱改文案 md —— git 有历史，随时可回滚；令牌权限只给这一个仓库的 Contents。
